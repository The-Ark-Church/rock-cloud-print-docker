Labels

Rock will not give you the ZPL for a label designed in its own designer. This gets it by being a printer: Rock sends the label here as if this were a printer, and this catches it instead of paper coming out. You will need to set up a new Printer Device in Rock and add this print proxy's IP address to the printer. You can then use the Label Designer's preview window to "print" to the newly created printer device you created. That will send it here for capture.

For a label you designed as a blank — with lines to write on and a placeholder where the code goes. A normal check-in label will not do: blanking one leaves empty space with nothing to say what goes where.

This proxy is at …

  1. Press Wait for a label below
  2. In Rock, Select a Label
  3. Click Label Designer
  4. Select Preview
  5. Print a label to the device you created in the preview window, then come back to the print proxy capture screen
  6. Choose which field holds the security code, give it a name, and save

Nothing here needs to be connected to Rock. Whichever proxy Rock already sends that label to is the one that opens the connection, so the address only has to be reachable from that proxy — it is an ordinary printer address as far as it is concerned. If that proxy is on another machine or another subnet, the address above has to be routable from there. Note that this also works with printing from the Rock server as well. No other print proxy is needed.

Which fields hold the security code?

What is Provided
This application includes 3 Pre-coded blanks for people to fill in by hand when check-in is down. Every copy carries one security code shared by all of its labels, so a child's tag and a parent's receipt still match at pickup.

How Made
A label is a ZPL file. You can generate a label file a few different ways, how you do it is up to you. You can use Labelary, Zebra Label Designer, write the ZPL yourself if you are a nerd (like I did). Once you have generated a file you can upload them. You can also create a label in the Rock Label designer Next-Gen Only, and use the capture feature to add them the easy way. Once you have labels, tick the checkboxes on the ones that you want to print as a set, and use the arrows to order them. The size is fixed in the file (your label ZPL), so load matching label stock in your printer. How many characters a code can have is fixed in the label you upload so make sure your security code length matches, e.g. the default labels are set up for a 3 random character security code, so setting 3 on the security code length is correct, any more than that and the characters might not display.

Tips
Add WWW where the code goes and it will be replaced with the security code generated here. Pick a printer that is not serving check-in. Sequential codes are remembered between runs and reserved before anything is sent, so a failed run leaves a gap rather than repeating itself later.

Security

PIN is set via environment variable. To change or remove it, update the Password variable in your docker-compose.yml and restart the container.

No PIN is set. Anyone who can reach this page has full access. Optionally set a PIN to require a login prompt.

PIN protection is enabled. Enter your current PIN to change or remove it. Leave New PIN blank to remove protection.

Reverse proxy

Set via environment variables. These come from the TrustReverseProxy and TrustedProxy variables in your docker-compose.yml. To change them, edit that file and restart the container.

Leave this off if people open this page directly. Turn it on only if they reach it through another device that passes their requests along, so that the login limit counts each person separately instead of everybody as the proxy.

Only requests arriving from this address may say which client they came from (in the X-Forwarded-For header); anything else saying so is ignored. Use the proxy's address as this container sees it, which may not be the one people type into their browser. Separate several with commas.
